# FlowPilot authenticated smoke-test fix v1

## Why this replacement is needed

The previous smoke test read `API_KEY` and `API_ADMIN_KEYS` only from the
current shell environment. When invoked as documented (`python
scripts/smoke_test.py`), it did not load the repository `.env`, so it sent no
`X-API-Key` header even though the API correctly required authentication.

The replacement reads missing variables from `.env` (process environment
still takes precedence), uses an operator/admin credential for workflow
creation, run polling and metrics, and uses a reviewer/admin credential for
the outreach approval endpoint. It never prints credential values and does
not turn off API authentication.

## Apply

From the FlowPilot repository root:

```bash
unzip -o /path/to/FlowPilot-Smoke-Test-Auth-Fix-v1.zip -d .
```

Then run:

```bash
python scripts/smoke_test.py
```

The default timeout is now 90 seconds per workflow. Override it with
`--timeout 120` if the configured model provider is slower. To use a different
environment file, pass `--env-file /path/to/file`.

The `.env` file should contain server-side role keys, normally generated by
`scripts/bootstrap_env.py`:

- `API_OPERATOR_KEYS` (or `API_ADMIN_KEYS` / legacy `API_KEY`) for workflow execution.
- `API_REVIEWER_KEYS` (or `API_ADMIN_KEYS` / legacy `API_KEY`) for outreach approval.

Do not commit `.env` or share its contents. The smoke test only reports whether
credentials are configured; it does not display them.
